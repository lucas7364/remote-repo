# 多渠道通知设计（短信、邮件、微信公众号）

#核心思想：**策略模式 + 工厂模式**，把不同通知渠道的实现做隔离，上层业务不关心底层是哪个渠道，面向抽象编程，新增渠道不用改业务代码，符合开闭原则。

#整体分层：

#1. 通知抽象接口：统一发送方法
#2. 各个渠道具体实现类：短信、邮件、公众号
#3. 工厂类：根据渠道类型获取对应的通知实现
#4. 通知上下文 / 服务：业务调用入口，组装参数，调用发送
#5. 通知 DTO：统一封装通知参数
#6. 可选：枚举定义渠道类型、异步发送、失败重试、记录发送日志

# 生产环境要考虑的点:

#1. **异步发送**：通知属于非核心流程，不能阻塞主业务，使用`Spring @Async` / MQ (RabbitMQ/RocketMQ) 异步发送；主业务只落通知任务，消费者消费发送。
   
#如果同步调用第三方接口，第三方超时会拖垮业务。

#2. **发送记录、状态持久化**：数据库存通知记录表，用户 id、渠道、接收人、内容、发送状态 (待发送 / 成功 / 失败)、错误信息、重试次数。
#3. **失败重试**：调用第三方接口失败，定时任务重试，限制最大重试次数，避免无限重试。
#4. **限流 & 防骚扰**：同一个用户短时间不能频繁发送短信。
#5. **模板管理**：短信、公众号都依赖模板，模板配置放数据库 / 配置文件，不要硬编码。
#6. **扩展性**：后续新增渠道（钉钉、企业微信、APP 推送），只需要新增类实现`NotifyStrategy`接口即可，**不需要修改原有业务代码**。


#技术栈：SpringBoot + Java
